# Data model

## 基本原则：记录“断言”，而不仅是“事实”

严格来说，“苏轼于某年担任某职”是某个来源提出的一条断言。未来正式数据库建议引入 `Assertion`：

```text
Assertion
- subject_id
- predicate
- object / value
- valid_time
- source_id
- source_locator
- certainty
- curator_note
```

这样，不同年谱对日期有分歧时可以同时保存。

## 核心实体

### Person

人物名称应拆分本名、字、号、谥号、异体字；籍贯和活动地不能混为一谈。

### Place

至少保存：

- 史料原文地名
- 标准化历史地名
- 当时行政层级和隶属
- 有效时间
- 现代对应
- 坐标与定位可信度

### Appointment

宋代官僚记录不能只用一个 `title` 字段。正式模型应继续拆分：

- 寄禄官 / 阶
- 职名、馆职与学士职
- 实际差遣
- 勋、爵、食邑
- 除授动作
- 任所
- 起止时间
- 离任原因

### Event

事件可连接多个人物、地点、机构、作品和其他事件。灾害还需要范围、持续时间、严重程度和政府响应。

### Relation

关系必须区分类型、方向、时间和证据。一次赠诗、长期友谊、师生关系和政治联盟不能是同一种边。

### Work

作品需要作者、成文时间、地点、文体、唱和对象、用典和版本等字段，并允许年代不确定。

### Source

来源应保存版本、卷次、页码或段落定位；网页 URL 只是辅助定位，不能替代正式书目。
