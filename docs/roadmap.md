# Roadmap

> 本路线图自 v0.3 起以《宋史》语料、证据阅读和研究查询为主线。苏轼 v0.2 是已经完成的模型验证案例，不再定义产品范围。

## 已完成基础 — v0.1 至 v0.2

- [x] React 展示原型与基本交互；
- [x] PostgreSQL + PostGIS 事实层；
- [x] 共享 Zod schema、API 和确定性 curated import；
- [x] Assertion、Evidence、TemporalExtent、Appointment 与 ServiceEpisode 最小链路；
- [x] 苏轼杭州至黄州仕宦、徐州洪水、乌台诗案和黄州安置回归集；
- [x] API 与 GitHub Pages 的 verified static projection；
- [x] 正式范围不静默回退到 demo 数据。

这些成果保留，但旧总览、人物网络和 prototype 统计不再作为下一阶段扩展基础。

## Phase 2 — 人工审核、纪传对读与通用查询（下一阶段）

- 神宗本纪候选实体、时间、除授和事件的人工审核工作流；
- 本纪与列传、志、表之间的 passage 对齐；
- 支持、限定、反驳和文本异同的并列界面；
- 人物、地点、官职、机构和事件的通用详情与反查；
- 原始纪年、时间精度、顺序和可选公历换算；
- 版本化研究集、可分享查询和 CSV/JSON 导出；
- 数据质量、审核状态和来源依赖统计。

Phase 2 的完成标准不是候选数量，而是人工审核、异说共存和 passage 回溯链可用。

## Phase 3 — 官制、历史地理与外部数据对齐

- 官、职、差遣、阶、勋、爵和处分身份的完整受控词表；
- 除授动作、任职状态、中央—地方流动和任期查询；
- 历史行政区实例、隶属、治所点和边界有效期；
- 与独立 `chushou` 项目的共享 schema 或模块边界；
- 在许可和引用条件明确后，对齐 CBDB 与 CHGIS；
- 外部数据库结果只作为独立来源或归一候选，不覆盖《宋史》原文层。

## Phase 4 — 跨史料校勘与专题研究

- 《续资治通鉴长编》、文集、墓志、地方志和年谱的来源对象与 passage；
- 同一事件或任命在多来源之间的对读、冲突和修正；
- 灾害、赈济与地方治理；
- 科举、家族和社会流动；
- 党争、同年、荐举和政治网络；
- 战争、外交、财政、物价和行政区划；
- 作品编年、创作地点、唱和和文本主题。

专题只有在来源范围、统计单位、审核状态和重建查询明确后才成为正式研究视图。

## Phase 5 — 可复现发布与协作研究

- 研究快照、数据集版本和永久引用；
- 查询定义、CSV/JSON/GeoJSON 和图投影导出；
- 整理者任务、审核队列、修改历史和责任归属；
- 公共数据发布、许可清单和可引用版本；
- 中英文界面；
- 为 AI 提供只引用可追溯 passage/assertion/evidence 的研究上下文。

## 持续约束

所有阶段都必须：

- 先说明研究问题和数据覆盖，再设计可视化；
- 保留史料原文、归一结果和研究判断的分层；
- 不把全文命中数当作事件数；
- 不把 candidate 或 AI 输出直接升级为 accepted；
- 不因 API、数据库或正式数据缺失而回退到 demo；
- 从版本化输入确定性重建数据库和研究投影；
- 让每项前端历史陈述能够回到 assertion、evidence 和 source passage。
