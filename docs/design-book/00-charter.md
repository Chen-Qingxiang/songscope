# 00　项目宪章

## 0.1 使命

SongScope（观宋）旨在建立一套可以被人阅读、被机器计算、被史料核验的宋史数字基础设施。

它的最终产物不只是一个网站，而是一组相互配合的能力：

- 结构化记录宋代人物、地点、机构、官职、作品和历史事件；
- 保存每条知识的出处、版本、定位、解释过程和不确定性；
- 支持人物年谱、仕宦路径、历史地图、关系网络和统计分析；
- 允许研究者提出自定义问题，而不是只浏览预制页面；
- 为 AI 提供可核验、可引用、可纠错的历史知识上下文；
- 逐步形成开放、可复用的宋史研究数据集。

## 0.2 不是什么

SongScope **不是**：

- 把维基百科内容换个界面展示；
- 只围绕苏轼制作的个人年谱；
- 将所有古籍全文塞进向量数据库后做问答；
- 只有节点和连线、缺少证据的“知识图谱”；
- 用一张巨型表格容纳全部历史信息；
- 以现代行政区、现代官名或精确公历日期强行覆盖历史语境；
- 通过模型生成大量无法追溯来源的“史实”。

## 0.3 主要用户

### 研究型用户

需要比较、统计、筛选、下载数据，并检查证据链。

### 深度阅读者

希望从人物、作品或事件进入，在时间、空间和关系之间自由跳转。

### 数据整理者

负责录入、校勘、消歧、合并、标注来源与处理冲突。

### 开发者与 AI Agent

依据稳定 schema 导入数据、构建视图、执行查询和生成可核验解释。

## 0.4 研究问题驱动

模型必须至少能支持下列类型的问题：

1. 苏轼在何时以何种官、职、差遣身份处于何地？
2. 某次“徙知”是任命动作、实际赴任，还是后世概括？
3. 一位官员的仕途由哪些任命、辞免、罢黜、起复和实际任职阶段构成？
4. 同一事件在《宋史》《长编》、年谱和文集中如何记载，彼此是否冲突？
5. 哪些人物通过同年、同乡、师生、婚姻、荐举或唱和形成网络？
6. 灾害发生后，地方官采取了什么措施，响应时间有多长？
7. 某一地区在不同时期叫什么、隶属哪里、边界如何变化？
8. 某词牌、意象、地点或政治语汇在时间与作者之间如何分布？
9. 进士名次、家族背景、籍贯与最高官位之间是否存在统计关系？
10. 一张图上的每个点、每条线和每个数字来自哪些史料记录？

无法服务真实研究问题的复杂模型，不应仅因“语义上漂亮”而进入核心系统。

## 0.5 成功标准

SongScope 的成功不以页面数量或数据总行数衡量，而以以下指标衡量：

- **可追溯率**：正式数据中具有有效证据定位的记录比例；
- **可区分率**：史料原文、标准化结果和研究判断是否被明确区分；
- **时间完整性**：涉及历史变化的记录是否保存有效期和精度；
- **冲突保留率**：互相矛盾的材料是否被并存，而不是静默覆盖；
- **查询能力**：核心研究问题能否通过稳定查询得到答案；
- **复现能力**：统计图能否由版本化数据和代码重新生成；
- **扩展成本**：加入新专题时是否需要破坏既有模型。

## 0.6 设计方法

采用“本体设计—真实案例—schema—查询—可视化”的循环：

```text
提出研究问题
    ↓
抽取真实史料案例
    ↓
设计或修正概念模型
    ↓
写成可校验 schema
    ↓
录入案例并运行查询
    ↓
用视图验证是否真的有用
```

设计书不是先写完再实施，而是在每轮真实数据验证后升级版本。
