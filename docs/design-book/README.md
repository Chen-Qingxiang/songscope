# 《观宋设计书》

> **SongScope Design Book — A Computational Laboratory for Song History**

本书是 SongScope 的最高层设计规范。它回答的不是“页面应该长什么样”，而是：

> 如果在数字时代重新组织宋史知识，什么应当被视为对象、事件、关系、时间、地点、证据与研究结论？

SongScope 的代码、数据库、导入器、API、可视化和 AI 功能，都应当服从本书定义的原则。若实现与本书冲突，应先修改设计书或提交明确的架构决策记录，而不是让代码悄悄形成另一套事实标准。

## 当前状态

- 版本：`0.2-draft`
- 性质：可实施的架构基线，不是封闭不变的终极本体
- 已完成验证对象：苏轼仕宦、迁徙与政治事件
- 当前产品中心：《宋史》语料、纪事索引、证据阅读与研究查询
- 当前结构化切片：卷十四至卷十六神宗本纪
- 长期重点专题：宋代官制与除授
- 数据范围：北宋、南宋及其相关政权、人物和文献

## 核心判断

1. **SongScope 是证据驱动的历史知识平台，不是百科全书。**
2. **历史知识应区分实体、事件、关系、断言、证据和研究视图。**
3. **史料所说、整理者所录、系统所归一、研究者所判断必须分层保存。**
4. **时间、地点、身份和官职都具有历史有效期，不能被当作静态字符串。**
5. **同一问题允许多个互相冲突的断言并存。**
6. **关系型数据库作为第一阶段事实存储；知识图谱是语义投影和交换形式，不是先决条件。**
7. **任何统计值、地图点和网络边都必须能够反查到记录与证据。**
8. **先用真实案例压测模型，再扩充数据；不做脱离史料的宏大空壳。**

## 规范用语

本书使用以下词语表达约束强度：

- **必须**：不满足即不符合 SongScope 核心规范。
- **应当**：原则上必须满足；例外需要记录原因。
- **可以**：允许的实现选择。
- **暂不**：当前阶段有意不实现，但模型不得阻断未来实现。

## 如何修改本书

涉及以下内容的变更，应通过单独 PR，并附至少一个真实宋史案例：

- 新增或删除核心实体类型；
- 改变 `Assertion`、`Evidence`、`TemporalExtent` 或 `Appointment` 的语义；
- 改变公共 ID 规则；
- 改变来源追溯要求；
- 改变数据库的事实层与投影层边界。

小范围字段补充和词表扩充可以随功能 PR 一并提交，但必须同步更新相应章节和 schema 测试。
