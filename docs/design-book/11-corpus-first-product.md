# 11　以《宋史》语料为中心的产品重定向

## 11.1 本章地位

本章规定 SongScope 在完成 v0.2 苏轼证据链验证之后的产品中心与下一阶段实现边界。

本章不推翻前十章定义的实体、事件、状态、断言、证据、时间和官制语义。它修正的是实现顺序和用户入口：苏轼继续作为复杂模型的回归案例，但不再作为平台默认人物或产品身份。

若本章与下列旧文档在产品优先级上冲突，以本章为准：

- `09-su-shi-validation.md`：历史模型验证案例；
- `10-implementation-contract.md`：已经完成的第一阶段实现契约；
- `docs/implementation-v0.2.md`：v0.2 交付记录；
- 2026-07-13 以前的 `docs/roadmap.md`：旧实施顺序。

核心数据模型发生变化时，仍必须同时遵守相关设计章节，不得只凭本章静默改表。

## 11.2 偏航诊断

苏轼最初承担的是纵向压测任务：用少量真实史料同时检验除授、实际任职、迁徙、灾害、政治案件、地点与证据链。这个选择证明了模型可以工作，却在前端形成了错误的产品重心：

- 验证样本成为首页和全局状态；
- 时间轴、地图和人物网络成为一级导航；
- 数据模型的可扩展性被当作当前研究能力；
- 原文只能从结论的证据抽屉中被动查看；
- 用户不能从《宋史》卷、篇、段落出发浏览、检索和比较；
- prototype 统计与 verified 数据同时出现，削弱了覆盖范围的可理解性。

这不是证据模型失败，而是投影层反客为主。下一阶段必须把产品入口重新放回史料层。

## 11.3 产品定义

SongScope v0.3 及后续版本的第一产品定义为：

> 以《宋史》为首要语料的结构化纪事索引、证据阅读器与可复现研究查询平台。

“以《宋史》为首要语料”不等于把《宋史》的每句话直接宣布为历史真相。平台必须始终区分：

1. 《宋史》在某个载体的某个位置写了什么；
2. 整理者如何分段、标记和归一；
3. 系统从文本中提出了什么候选结构；
4. 研究者当前接受、质疑或拒绝什么断言；
5. 其他史料如何支持、限定或反驳该断言。

面向用户，产品形成三种相互连接的工作方式：

- **读史**：按篇类、卷、章节、纪年和段落阅读与检索《宋史》；
- **辨史**：查看文本标注、断言、证据、异说和整理活动；
- **用史**：在明确覆盖范围内筛选、比较、统计、导出并保存研究查询。

## 11.4 语料链路

下一阶段的规范链路为：

```text
SourceWork：《宋史》
  ↓
SourceItem：目录页或某一逐卷页的固定 revision / 抓取快照
  ↓
SourceUnit：篇类 / 卷 / 章节
  ↓
SourcePassage：稳定、有序、保存原文的段落
  ↓
TextAnnotation：文本跨度与实体、时间、官职、事件候选
  ↓
Assertion + Evidence：可审校的陈述和证据关系
  ↓
DomainRecord：人物、地点、事件、除授、状态等强类型记录
  ↓
Projection：纪事索引、表格、时间轴、地图、网络和统计
```

前端的任何简述、事件卡、数字、点或边必须能沿这条链返回到具体 `SourcePassage` 和来源版本。

## 11.5 SourceItem 与可复现获取

电子转录不是抽象作品本身。v0.3 把目录页和每个逐卷页分别建为 `SourceItem`；版本化 manifest 再把这些固定页面组成一次 `CorpusSnapshot`。不能用一个只写目录 revision 的来源对象代表随后变化的 496 个逐卷页面。

每个用于批量语料的 `SourceItem` 必须记录：

- 所属 `SourceWork`；
- 提供者和页面标题；
- 稳定 URL 或外部页面 ID；
- 固定 revision ID 或等价版本标识；
- 获取时间和获取方法；
- 适用许可、署名与再利用说明；
- 原始响应或规范化文本的内容校验值；
- 文字转换、标点、清理和分段规则版本；
- 已知缺页、乱码、重复和版本限制。

目录页 `SourceItem` 承载篇类和目录顺序；逐卷页 `SourceItem` 承载该卷正文及自己的 revision。`SourceUnit` 的父子层级可以跨这两类 item：例如卷十四的 `juan` unit 归属于卷十四页面 item，但其父 `work_division` unit 归属于固定目录页 item。实现必须显式测试这种关系，不能把网页容器关系误当成作品结构。

网络获取与数据库导入必须分开：

- `acquire` 可以访问外部来源并生成固定快照；
- `validate`、migration、seed/import、测试和构建必须只依赖已经固定的本地输入；
- 外部页面变化不得使相同数据版本的数据库重建结果变化；
- 更新 revision 必须形成新的数据集版本和差异报告。

## 11.6 SourceUnit

`SourceUnit` 表示载体中的层级和顺序，不把卷名当作自由文本散落在 locator 中。

最低字段语义：

```text
SourceUnit
- sid
- source_item_id
- parent_unit_id
- unit_type          work_division / juan / chapter / section
- label_original
- label_normalized
- sequence_index
- external_anchor
```

《宋史》的本纪、志、表、列传、附录属于 `work_division`；卷属于 `juan`。章节是否单独建层，应依据载体结构决定，不能根据现代页面视觉效果虚构史书原有层级。

## 11.7 SourcePassage

`SourcePassage` 是全文阅读、引用、标注和证据定位的共同基础。

最低字段语义：

```text
SourcePassage
- sid
- source_unit_id
- sequence_index
- source_text
- normalized_text?       # 可选，绝不覆盖 source_text
- checksum
- segmentation_method
- segmentation_version
- review_status
```

约束：

- `source_text` 必须保存获取快照中的文字，不得用简体转换或现代标点结果覆盖；
- 展示层可以提供简繁转换或断句视图，但必须标明方法并允许回看载体文本；
- SID 必须由固定来源身份、卷次和稳定段落序号形成；
- 同一快照和同一分段规则必须生成相同 SID、顺序和校验值；
- 分段规则改变时必须生成可审计迁移或新版本，不能使旧 locator 静默漂移；
- `SourceLocator` 应指向 passage 及可选文本跨度，而不是把摘录副本当作唯一原文。

## 11.8 TextAnnotation

`TextAnnotation` 表示文本跨度上的候选或已审核标记，例如：

- 人名、地名、机构名和书名；
- 年号、年、月、日和相对时间；
- 官、职、差遣、阶、爵、处分身份；
- 除、授、迁、徙、罢、落、夺、复等动作词；
- 灾害、战争、奏议、审判、迁徙等事件候选；
- 原文异体、缺字、衍文和疑读。

最低字段语义：

```text
TextAnnotation
- passage_id
- start_offset
- end_offset
- surface_text
- annotation_type
- target_entity_id?
- normalized_value?
- status              candidate / reviewed / rejected
- method
- curation_activity_id
```

偏移量的编码单位必须固定并测试；`surface_text` 必须与指定跨度匹配。自动抽取和 AI 生成只能创建 `candidate`，不得直接创建 `accepted` 断言。

## 11.9 从标注到断言

文本中出现一个名称或动作词，不等于系统已经确认一个历史事实。

```text
“徙知密州”文本跨度
  → 人物、动作、职事和地点候选标注
  → proposed assertion
  → 人工核对上下文、身份和时间
  → accepted / contested / rejected
  → appointment action 与后续 service episode 投影
```

必须保留以下区别：

- 全文命中次数不等于事件次数；
- 动作词命中不等于成功除授；
- 本纪条目不等于完整事件；
- 人名字符串不等于已消歧人物；
- 史料叙述顺序不等于精确日期；
- 电子转录中的标点不等于原书固有标点。

## 11.10 第一用户流程

### 从史料出发

```text
打开《宋史》目录
→ 选择篇类与卷
→ 按原顺序阅读段落
→ 查看原始纪年、文本标注和整理状态
→ 跳转人物、地点、官职或事件
→ 查看相关段落与证据
```

### 从检索出发

```text
检索原文或规范名称
→ 查看命中总数和明确覆盖范围
→ 按篇类、卷、纪年和审核状态筛选
→ 打开上下文段落
→ 将文本命中加入研究集或导出
```

### 从研究问题出发

```text
选择版本化研究查询
→ 检查统计单位、过滤条件和数据覆盖
→ 查看表格结果
→ 必要时切换时间轴、地图或网络投影
→ 反查每条组成记录和来源段落
→ 导出数据、查询定义和引用信息
```

## 11.11 信息架构

v0.3 的一级入口应当围绕任务，而不是围绕图形类型：

- **史料**：作品、篇类、卷和段落阅读；
- **检索**：原文、实体和规范字段搜索；
- **纪事**：在已覆盖范围内按史料顺序或时间浏览；
- **实体**：人物、地点、机构、官职、事件和作品；
- **研究查询**：版本化筛选、表格、导出和研究快照；
- **数据版本**：来源、覆盖率、审核状态、缺失和许可。

“数据模型”属于文档与开发者入口，不应占据面向读者的一级研究导航。

## 11.12 可视化准入规则

时间轴、地图、网络和图表只有同时满足以下条件才可作为正式研究视图：

1. 对应一个写明的研究问题；
2. 显示数据集版本和覆盖范围；
3. 说明统计单位和过滤条件；
4. 区分 raw passage、candidate/reviewed annotation 与 proposed/accepted/contested assertion；
5. 每个图形元素能够返回组成记录和 passage；
6. 结果可以用版本化查询重建；
7. 数据不足时显示缺失，不用 prototype 填充。

地图和网络不再因“平台应该有地图/网络”而成为默认入口。

## 11.13 v0.3 语料与结构化范围

### 原始可检索语料

- 抽象作品：脱脱等《宋史》；
- 电子转录载体：中文维基文库《宋史》目录及其逐卷页面；
- 预期书目结构：本纪、志、表、列传、附录，共 496 卷；
- 实际覆盖：以固定目录 revision 中可发现并成功固定的页面为准；
- 所有缺卷、未链接页、获取失败和空文本必须进入机器可读覆盖报告，不得静默宣称全书完整；
- 每个卷页固定自己的 revision ID、页面 URL、历史页或署名入口、许可和 checksum；
- 该载体是可检索电子转录，不是权威点校本；原始作品与网页整理层的版权和署名信息分别记录。

### 首个连续结构化切片

首个结构化切片为《宋史》卷十四、卷十五、卷十六，即神宗本纪一至三。

选择理由：

- 是连续完整的本纪时段，而不是单个人物生涯；
- 可以形成按原始纪年与条目顺序浏览的纪事骨架；
- 涉及多人物、多机构、多地点、多类事件和大量除授动作；
- 与现有苏轼杭州至黄州案例时间相交，可以验证本纪和列传之间的连接，而不再由苏轼定义平台范围；
- 能暴露“全文命中—候选标注—人工断言—研究投影”之间的真实差异。

v0.3 可以自动生成候选标注和 proposed assertion，但新增内容在人工审核前不得成为 accepted 正式断言。既有 v0.2 accepted 数据继续保留并作为回归集。

## 11.14 v0.3 必须回答的查询

1. 当前固定的《宋史》目录预期有多少卷，实际获取、校验、分段和可检索各有多少卷？
2. 如何按本纪、志、表、列传和卷次浏览原文？
3. 如何打开神宗本纪某一条原文，并查看其原始纪年、前后文和稳定引用？
4. “徙知”在当前可检索语料中出现于哪些段落？这些结果必须标为文本命中，而不是任命次数。
5. 神宗本纪中有哪些除授动作词候选？哪些已经人工审核，哪些尚未审核？
6. 某人物或地点在神宗本纪和现有苏轼列传切片中分别出现于哪些 passage？
7. 某条 accepted 苏轼断言如何回到卷338 passage；若神宗本纪存在相关文本，如何并列显示而不静默合并？
8. 任一查询如何导出原文定位、数据状态、数据集版本和查询定义？

## 11.15 非目标

v0.3 暂不：

- 完成 496 卷的实体消歧和 accepted 事件抽取；
- 把中文维基文库电子转录宣称为权威点校本；
- 自动将 AI 抽取结果升级为正式史实；
- 完成苏轼全生涯或作品编年；
- 批量导入 CBDB、CHGIS 或其他数据库填充页面；
- 构建通用聊天问答来代替原文检索；
- 继续增加无研究问题的仪表盘、地图动画或人物网络；
- 为追求视觉完整而回退到 demo 数据。

## 11.16 成功标准

本轮重定向成功，不以新增页面数量衡量，而以以下链路是否可运行衡量：

```text
固定的《宋史》电子转录快照
→ 可验证的卷与 passage
→ 原文浏览和全文检索
→ 候选标注与审核状态
→ 断言、实体和既有正式数据
→ 版本化研究查询和导出
→ 可选且可回溯的可视化投影
```

当用户可以从《宋史》原文进入结构化知识，也可以从研究结果返回原文，并清楚知道覆盖范围、审核状态和版本时，SongScope 才从“证据化专题演示”转向真正的宋史数字研究平台。
