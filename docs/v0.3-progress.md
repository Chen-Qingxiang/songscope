# SongScope v0.3 实施记录

本文记录 `docs/implementation-v0.3.md` 各 checkpoint 的可复核结果。它不是完成声明；完成状态仍以实施契约第12节和实际验证证据为准。

## Checkpoint 0：基线、来源与存储决策

- 分支：从包含 corpus-first 规范提交 `2a3ff9e` 的本地 `main` 创建 `codex/corpus-first-v03`；
- 当前事实层：PostgreSQL + PostGIS，已有 source work/item/locator、assertion/evidence、event、appointment 和 service episode；
- 当前正式输入：`data/curated/`，共享 Zod schema 校验后确定性重建数据库；
- 当前 API：人物、仕宦、事件、断言证据、来源和实体搜索，尚无 corpus/unit/passage/全文检索/coverage 语义；
- 当前静态模式：从同一 curated JSON 生成 verified 投影，架构可扩展；
- 当前偏航：一级导航、首页和全局搜索仍以苏轼时间轴、地图、人物网络和 prototype 数据为中心；
- prototype 依赖：`src/data/songData.ts` 仍被首页统计、人物网络和数据模型页直接导入；
- 来源审计：固定目录 revision `2535238` 发现496卷，全部卷页可取得，原始 wikitext 约15.95 MiB；
- 存储与许可决定：见 [`adr/001-corpus-snapshot-storage.md`](adr/001-corpus-snapshot-storage.md)。

## Checkpoint 1：语料 schema 与固定输入

- 新增共享 corpus schema：revision-specific `SourceItem`、`CorpusSnapshot`、`SourceUnit`、`SourcePassage`、`TextAnnotation`、coverage 和固定文件格式；
- 新增 `npm run corpus:acquire`、`corpus:validate`、`corpus:coverage`；只有 acquisition 访问网络；
- 固定目录 revision `2535238` 和496个逐卷 revision，生成 `manifest.json`、`directory.json`、`units.json`、`coverage.json` 与496个卷文件；
- snapshot：`corpus:snapshot:songshi-wikisource:f3b6041f6161819b`；
- corpus version：`songshi-wikisource-r2535238-f3b6041f6161`；
- 覆盖：496 expected / discovered / acquired / validated / segmented / searchable，异常0；
- passage：39,924条；source wikitext 与可读文本投影分层保存；
- 卷十四、十五、十六生成1,340条 candidate annotation，覆盖 chronology、person、place、institution、office、appointment-action、event-term；
- 其余卷（包括卷338）只建立 raw passage，不生成未经批准的结构化断言；
- 连续运行 acquisition 后固定正文、manifest 和 content hash 不变；当前完整 snapshot 文件树 SHA-256 为 `a7460c4497b40e31edb9900453782f5637197be5ea03d92e3e8273de150a64cf`；
- corpus 校验测试覆盖元数据唯一性、许可、checksum、passage 顺序、annotation offset、结构化范围隔离和卷338原文可用性。

Checkpoint 1 验证：`corpus:validate` 通过；`typecheck` 通过；6 files / 26 tests 通过。
